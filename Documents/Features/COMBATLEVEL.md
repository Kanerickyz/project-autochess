# 战斗关卡

> 功能规格 · 只谈战场形状、半场与落点，不写具体格数与数值 · 2026-10-12  
> 相关文档：[战斗](./COMBAT.md) · [地图与节点](./MAP.md) · [游戏基础循环](./GAME_LOOP.md) · [游戏愿景](../GAME_VISION.md) · [角色单位](./UNITS.md) · [架构](../ARCHITECTURE.md)  
> **本版不写**：刷怪只数、移动速度等数值；战斗三步细则；地图选路；商店与牌库。  
> **【战场现状】** Run 主路径为 2D 俯视竖屏 18 列 × 32 行、硬半场投放与刷怪；开战后单位在连续坐标上实时移动（`scenes/combat/realtime/`）。旧线性开发关 `main.tscn` 仍是 4×8 回合制格子战斗。

## 1. 这是什么

**战斗关卡**规定：玩家从地图进入战斗类节点（战斗 / 精英 / Boss）之后，**战场长什么样、友方与敌方分别能落在哪一侧、开战前后空间怎么用**。

它不管「选哪个节点」（见 [地图与节点](./MAP.md)），也不管「准备 → 自动战斗 → 结算」三步怎么走、敌人**何时**刷（见 [战斗](./COMBAT.md)）。本篇只定**进场后的战场规格**。

| 本篇负责 | 别处负责 |
|----------|----------|
| 竖屏窄深、我下敌上、中线切半场 | **地图**：点哪个战斗类节点进来 |
| 预布阵 / cycle 只能落我半场；敌一次出齐只刷敌半场 | **战斗**：准备门槛、刷怪时机、胜负与结算 |
| 开战后天可越半场；各自寻最近敌；已上场不可拖 | **战斗 / 单位**：行动顺序、攻击与技能内容 |
| 逻辑格网 + 表现去格子化（投放感） | **技术美术 / UI**：相机、缩放、具体皮肤 |

## 3. 术语

| 说法 | 意思 |
|------|------|
| **战场** | 一场遭遇里双方单位活动的空间（逻辑格网 + 画面表现） |
| **中线** | 把战场上下对半切开的分界；行数为偶数时上下行数相等 |
| **我半场** | 靠近玩家一侧（画面下方）的半区；友方投放只许落这里 |
| **敌半场** | 靠近敌方一侧（画面上方）的半区；敌方刷出只许落这里 |
| **硬半场（投放）** | 准备预布阵与战斗中 cycle 补人：落点校验只认己方半场 |
| **越半场** | 开战之后单位移动与交战可以穿过中线，进入对方半场 |
| **逻辑格网** | 占位、距离、寻路用的矩形格子；玩家不必感到「在下跳棋」 |
| **去格子化表现** | 画面强调投放与站位区域，弱化或隐藏格线（类皇室战争投放感） |

## 4. 战场形状与朝向【设计定稿 / 已实现】

| 项 | 约定 |
|----|------|
| 朝向 | **竖屏窄深**：列少、行多；玩家在**下**，敌方在**上** |
| 中线 | 行数为**偶数**，中间切开，上下半场行数相等 |
| 格网 | 仍是矩形逻辑格；邻接与距离用现有棋盘接口，不用六边形替代 |
| 具体格数 | **18 列 × 32 行**（只借皇室战争的战场比例）；上下各 16 行；中线是行与行的分界，不单独占一行格子 |
| 河 / 桥 / 塔 | **都没有**；全场可通行 |

示意（非定稿格数）：

```text
        敌半场（上）
   ┌─────────────────┐
   │  敌方刷出落点区  │
   ├─────── 中线 ─────┤
   │  友方投放落点区  │
   └─────────────────┘
        我半场（下）· 玩家
```

## 5. 硬半场与开战规则【设计定稿 / 已实现】

### 5.1 投放（开战前与 cycle 补人）

| 谁 | 落点 |
|----|------|
| 友方预布阵 | **只许**我半场空格 |
| 友方 cycle 补人 | **只许**我半场空格；仍受人口与「已上场不可拖」约束（见战斗文档） |
| 敌方刷出 | **只许**敌半场空格；本场计划敌人**一次出齐**（时机见战斗文档：开战首回合一批） |

落点**吸附到格子中心**；落点格内已有任一单位中心则不可落，落地后若与别的单位重叠由推挤分开。敌方开战一次刷出，只落敌半场；实际刷出数不超过敌半场可落格数。

### 5.2 开战之后

- 开战后单位**不再受格子约束**：在连续坐标上实时移动与攻击，可以越过中线。距离以「格」为长度单位，按直线计算。  
- 选目标、碰撞推挤、部署时间见 [角色单位](./UNITS.md)。  
- 玩家**不可**拖动已上场的单位，不可点技能。

## 6. 逻辑格与表现

| 层 | 约定 |
|----|------|
| **逻辑** | 格子**只用于投放吸附**（预布阵、补人、刷怪落点）和半场划分；开战后位置、距离、碰撞都在连续坐标上计算 |
| **表现** | 去格子化：强调上下半场与投放区，弱化棋盘跳棋感；借鉴皇室战争的**投放感**，**不**做河、塔、推塔胜负 |

胜负仍是清光敌方 / 己方全灭（见愿景），不因半场改变。

## 7. 和相邻文档怎么分

```text
地图选路 → 进入战斗 / 精英 / Boss
  →【本篇】加载本场战场规格（半场、朝向、可落区）
  →【战斗】准备预布阵 → 自动战斗与 cycle 补人 → 结算
```

| 问题 | 看哪篇 |
|------|--------|
| 点哪个节点 | 地图 |

| 一整局何时进出会合 | 游戏基础循环 |

## 8. 玩家可观察操作与验收（L0）

1. 进入战斗类节点后，战场呈竖向：我在下、敌在上，中线可辨。  
2. 准备阶段只能把友方放到我半场；点到敌半场应失败或不可选。  
3. 开战时敌方在敌半场一次出齐（数量受敌半场空位限制）。  
4. 战斗中单位可越过中线交战；已上场友方不可被拖换位。  
5. cycle 补人同样只能落我半场。  
6. 画面有投放区感，不依赖「满盘抢空闲格」制造压力。

自动化覆盖：`scripts/ui/realtime/realtime_battle_flow_test_runner.gd`（2、3、5 及开战门槛）；1、4、6 靠 GUI 验收。

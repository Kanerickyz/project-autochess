# 战斗关卡

> 功能规格 · 战场空间、半场区域与投放规则 · 2026-10-13  
> 相关文档：[战斗](./COMBAT.md) · [地图与节点](./MAP.md) · [游戏基础循环](./GAME_LOOP.md) · [游戏愿景](../GAME_VISION.md) · [角色单位](./UNITS.md) · [架构](../ARCHITECTURE.md)  
> **本版不写**：刷怪只数、移动速度、占位半径等数值；战斗三步细则；地图选路；商店与牌库。  
> **【战场现状】** Run 主路径为 2D 俯视竖屏、硬半场投放与刷怪；开战后单位在**有界连续平面**上实时移动与碰撞（`scripts/combat/realtime/`）。旧线性开发关 `main.tscn` 仍是 4×8 回合制格子战斗（**非**本篇目标规格）。

## 1. 这是什么

**战斗关卡**规定：玩家从地图进入战斗类节点（战斗 / 精英 / Boss）之后，**战场长什么样、友方与敌方分别能落在哪一侧、开战前后空间怎么用**。

它不管「选哪个节点」（见 [地图与节点](./MAP.md)），也不管「准备 → 自动战斗 → 结算」三步怎么走、敌人**何时**刷（见 [战斗](./COMBAT.md)）。本篇只定**进场后的战场空间规格**。

| 本篇负责 | 别处负责 |
|----------|----------|
| 竖屏窄深、我下敌上、中线切半场**区域** | **地图**：点哪个战斗类节点进来 |
| 预布阵 / cycle 只能落我半场；敌一次出齐只刷敌半场 | **战斗**：准备门槛、刷怪时机、胜负与结算 |
| 连续战场边界、投放吸附、越线交战 | **角色单位**：占位圆、移速、索敌、推挤、部署时间 |
| 投放区表现（皇室战争式投放感） | **技术美术 / UI**：相机、缩放、具体皮肤 |

## 2. 写什么、不写什么

### 2.1 本文要说清的

- 战场朝向与有界连续平面（功能语言；参考尺寸可写，不作战斗逻辑格）  
- **两层空间**：投放格网（只帮玩家落点） vs 开战后的连续坐标  
- 硬半场：投放区 vs 开战后全战场可移动区  
- 与战斗三步、地图选路的分工  
- 现状与目标对照  

### 2.2 本版不写

具体宽×高、刷怪数量、节奏秒数交给数值；三步流程与胜负见战斗文档；选路见地图。借鉴只借「投放感」，不抄河与塔。

**本版不作为主路径规格的内容**（仅旧工具环或实现债可能出现）：回合制行动轮、按格邻接寻路、四向/八向步进、一格一人、切比雪夫/曼哈顿格距战斗、技能「周围格子」的格点语义。连续战场上技能的空间说法见技能文档，与格点棋盘脱钩。

## 3. 术语

| 说法 | 意思 |
|------|------|
| **战场** | 一场遭遇里双方单位活动的**有界二维连续平面**（世界坐标）；长度单位用「格」，与参考投放格网同一尺度 |
| **连续坐标** | 开战前后单位圆心所在的 `(x, y)`；开战后位置、距离、碰撞、移动都在此计算 |
| **中线** | 把战场上下对半切开的**区域界**（不是「占一格的中线格」） |
| **我半场 / 敌半场** | 画面下方 / 上方半区；**投放与刷出**分区用 |
| **硬半场（投放）** | 准备预布阵与战斗中 cycle 补人：落点校验只认**我半场** |
| **越半场** | **开战之后**单位可在全战场移动与交战，可穿过中线进入对方半区 |
| **投放格网** | 仅用于**玩家投放与刷怪落点吸附**的矩形参考格（如 18 列 × 32 行）；**不**承担开战后的占格、邻接或寻路 |
| **投放吸附** | 玩家点选后，落点 snap 到最近格心（或等价规则），再按占位圆做合法校验 |
| **合法投放** | 在半场合规、人口未满、占位圆与已有单位不非法重叠（见 §5） |
| **投放区感（表现）** | 画面强调上下半场与投放区域，弱化跳棋格线；逻辑仍是连续平面 |

## 4. 战场形状与朝向【设计定稿】

| 项 | 约定 |
|----|------|
| 朝向 | **竖屏窄深**：玩家在**下**，敌方在**上** |
| 平面范围 | 有界矩形区域；世界坐标 `(x, y)`，`x` 横向、`y` 纵向（向上为敌方向） |
| 参考尺寸 | **18 格宽 × 32 格高**（借皇室战争比例）；上下各约 16 格高；中线为 **`y = 16` 的区域界**（不单独占「一行格子」） |
| 通行 | 平面内无河、桥、塔；障碍格/地形若将来加入，另开切片，本版默认全场可通行 |
| 六边形 / 格点战斗 | **不做**；不开战后的格点邻接体系 |

示意（比例示意，非数值定稿）：

```text
        敌半场（上）· 刷出区
   ┌─────────────────┐
   │   连续平面       │
   ├────── 中线 ──────┤
   │   连续平面       │
   └─────────────────┘
        我半场（下）· 投放区 · 玩家
```

## 5. 连续空间规则【设计定稿】

### 5.1 占位与距离

| 项 | 约定 |
|----|------|
| 占位形状 | 每个单位是一个**圆**（半径见角色单位 `body_radius`） |
| 重叠 | 圆与圆**不应**长期重叠；挤在一起时按质量推挤（见角色单位） |
| 距离 | 索敌、攻击范围、溅射等一律用连续坐标上的**直线距离**（单位：格） |
| 边界 | 圆心应保持在战场有界范围内；贴边行为由实现定义，本篇要求「不能走出战场」 |

### 5.2 移动（开战后）

- 单位在连续平面上**实时**移动，默认**寻路靠近目标**并做简单避障/绕行；差异主轴是**移动速度**（每秒可移动的距离），不是多种「走法身份」。  
- **不**使用格点四向/八向步进、斜穿格缝、象棋式移动图案作为主路径规则。  
- 固定逻辑时间步推进，结果不依赖显示帧率（见战斗文档）。  
- 玩家**不可**拖动已上场单位，**不可**点技能。

### 5.3 投放（开战前与 cycle 补人）

| 谁 | 落点 |
|----|------|
| 友方预布阵 | **只许**我半场；**合法投放** |
| 友方 cycle 补人 | **只许**我半场；人口与「已上场不可拖」见战斗文档 |
| 敌方刷出 | **只许**敌半场；本场计划敌人**开战时一次出齐**（时机见战斗文档） |

流程（功能层）：

1. 在半场合规的指针位置，**吸附**到投放格网格心（或等价 snap）。  
2. 以该点为圆心放置占位圆；若与已有单位非法重叠，则**拒绝**本次投放。  
3. 若轻微重叠，落地后由推挤分开（与开战后的推挤同一套语义）。  

刷怪：在敌半场内选取合法位置（同样可按格心候选 + 占位校验）；实际刷出数受**敌半场内还能放下多少个体**限制，而不是抽象「空闲格数」表。

### 5.4 开战前后对比

| 阶段 | 空间怎么用 |
|------|------------|
| 投放 | 格网 **只**负责 snap 与半场分区；合法性看**区域 + 占位圆** |
| 开战后 | 只在**连续坐标**上更新位置；可**越半场**；无格点占格、无行动轮 |

## 6. 逻辑与表现

| 层 | 约定 |
|----|------|
| **逻辑** | 连续平面 + 圆占位 + 区域半场；投放格网仅为 snap 与策划对齐尺寸的参考 |
| **表现** | 强调上下半场与投放区；单位移动可格间插值，**不要求**玩家感到在下跳棋 |
| **胜负** | 仍为清光敌方 / 己方全灭（见愿景），不因半场改变 |

## 8. 玩家可观察操作与验收（L0）

1. 进入战斗类节点后，战场呈竖向：我在下、敌在上，中线可辨。  
2. 准备阶段只能把友方**合法投放**到我半场；点到敌半场应失败或不可选。  
3. 开战时敌方在敌半场一次出齐（数量受敌半场**还能放下多少**限制）。  
4. 战斗中单位在连续平面上移动，可越过中线交战；已上场友方不可被拖换位。  
5. cycle 补人同样只能在我半场**合法投放**。  
6. 画面有投放区感，压力来自半场分区与越线，而非「满盘抢空闲格」。

自动化覆盖：`scripts/ui/realtime/realtime_battle_flow_test_runner.gd`（2、3、5 及开战门槛）；1、4、6 靠 GUI 验收。

# 主题羁绊

> 功能规格 · 只谈主题标签与凑人触发的团队效果规则，不写具体成形人数与效果点数 · 2026-11-03  
> 相关文档：[游戏愿景](../GAME_VISION.md) · [角色单位](./UNITS.md) · [角色技能](./UNIT_ABILITIES.md) · [战斗](./COMBAT.md) · [玩家](./PLAYER.md) · [Content 角色库](../Content/UNITS_ROSTER.md) · [架构](../ARCHITECTURE.md)  
> **本版不写**：各主题成形阈值、团队层具体点数、HUD 色板定稿、敌方是否计主题。  
> **【用户新共识 · 设计定稿】** 可招友方按 **八主题** 挂主/辅标签；**上场**同主题人数达门槛触发团队效果；**多标签分别计数**；**无人无主题**。效果须走统一效果管线。**【As-Is · 部分已实装】** `UnitData` 主题字段、上场计数/成形、开战占位 `EffectSpec` 与信息卡主题行已接；成形人数与效果点数仍为可配置占位；**无羁绊 HUD 成形高亮**；**文档 To-Be ≠ 全部已实现**。

## 1. 这是什么

**主题羁绊**规定：每名可招友方带有 **主主题**（必有）与可选 **辅主题**；战斗中按**已入座上场**的友方角色统计各主题人数，达成形门槛后发放**该主题一层团队效果**。

它与 [队伍羁绊台词](./UNIT_PARTY_BARKS.md) 无关（后者纯表现）。它也不是技能目标里的「按标签筛选队友」（见角色技能）；主题羁绊是 **凑人数触发的团队层**。

体验骨架：养队时看得见身份 → 上场凑同主题 → 开战观战里兑现一层可读的团队态势；深度仍主要来自单位技能与站位，主题层是身份开关，不是第二套技能树。

## 2. 写什么、不写什么

### 2.1 本文要写清的

- 八主题清单与分家口诀  
- 主/辅标签规则与计数口径（含双计）  
- 成形与发放时机（功能层）  
- 与技能 / 增益 / 随从 / 熔印者的边界  
- 效果管线约束与分轴原则  
- 验收口径  

### 2.2 和别处怎么分

| 本篇负责 | 别的文档负责 |
|----------|----------------|
| 主题表、计数、成形触发、团队层原则 | **Content 角色库**：每名友方的主/辅归属 |
| 主题层须走统一效果管线 | **角色技能**：单位内建技能；`allies_with_tag` 等筛选 |
| — | **增益卡**：商店挂成员的持久强化 |
| — | **战斗 / 战斗反馈**：观战如何显示已成形主题（表现细则可后补） |
| — | **数值**：成形人数、各主题效果点数与档位 |

### 2.3 一句边界

**做**：八主题；主+可选辅；上场双计；少档成形；团队层走 `EffectSpec` / `EffectResolver`。  
**不做**：无主题角色；备战计入；战斗生成的代理角色计入；另写一套羁绊专用 Buff；种族/职业「第二套标签表」与主题并行对外。

## 3. 术语

| 术语 | 意思 |
|------|------|
| **主题** | 玩家可见的阵营身份之一（八类之一） |
| **主主题** | 每名可招友方必有的一个主题 |
| **辅主题** | 可选的第二个主题；无则空 |
| **双计** | 一名上场友方若带主+辅，则其主、辅主题人数各 +1 |
| **成形** | 某主题上场人数达到该主题门槛，发放该主题团队层 |
| **主题团队层** | 成形后挂在己方（功能范围见 §6）的战斗效果；遭遇结束清除（除非规格另定永久类——本版默认**仅本场**） |

## 4. 八主题清单与分家

| 主题 | 口诀 | 主要装谁 |
|------|------|----------|
| **护卫** | 挡住——承伤、防反、护阵 | 塔盾 / 板甲 / 囤血 / 续命厚盾 |
| **骑士团** | 旗号与骑乘——编制、坐骑、禁卫旗 | 骑乘、禁卫、旗手、军弩编制 |
| **战士** | 近战砍——狂战、巨斧、破阵输出 | 近战输出与听血成长 |
| **工匠** | 打造与奇械——甲、药、火器、爆炸 | 甲胄师、火铳、爆爆、药师等 |
| **亡灵** | 死与魂——退场、墓园、召从亡者 | 枯骨、召魂、残影、葬焰等 |
| **军乐队** | 鼓号节奏——战鼓、号角、鼓阵 | 鼓手、号手、四鼓 |
| **秘术** | 咒与奥——法、影、祝圣、修士 | 奥术、散咒、影刺、愈修等 |
| **佣兵** | 散兵与账房——游猎火力、发饷收金 | 游侠、猎手、经济四人等 |

**护卫 ≠ 骑士团**：护卫=挡；骑士团=旗号与骑乘。  
经济四人（饷吏 / 殓金 / 帑卫 / 血饷）均可进入**佣兵**计数（主或辅），归属以 Content 表为准。

具体每名友方的主/辅见 [UNITS_ROSTER.md](../Content/UNITS_ROSTER.md)「主题归属」。

## 5. 标签与计数规则

1. **可招友方**每人 **恰好 1 个主主题**；**至多 1 个辅主题**；**禁止无主题**。  
2. **只计已入座上场**的友方角色；**备战不计**。  
3. **战斗中生成的代理角色（随从）默认不计**主题人数。  
4. **多标签双计**：同时带主与辅的上场成员，对两个主题各贡献 1 人。  
5. **敌方角色**本版是否计主题、是否享受主题层——**默认不计、不享受**（若日后要对打镜像另开修订）。  
6. **熔印者**：归属规则另定；未定前 **不挂主题、不计入**（避免真空期误计）。

---

## 6. 成形与发放（功能，不定点数）

1. **门槛**：每主题优先 **一档成形**；第二档仅当叙事与强度需要时再开，且应明显更稀（点数与人数归数值）。  
2. **结算时机**：默认在**开战锁定阵容之后**根据上场名单结算；本场减员**不降低**已成形状态（避免观战中反复开关）；新增生成代理**不**抬主题人数。  
3. **发放对象**：默认己方上场友方（含是否含无技能白板——见 §7 军乐原则）；具体选择器写在效果描述里。  
4. **持续时间**：默认**本场战斗**；遭遇结束清除。  
5. **管线**：主题团队层必须表示为普通效果描述，经 `EffectSpec` + `EffectResolver` 结算；触发可挂开战或可观察节点；**禁止**平行羁绊 Buff 脚本。

---

## 7. 与技能分轴与防膨胀原则

1. **主题层 = 弱身份开关**：全队同向、可读；单位内建技能与站位仍是主乘法（见构筑乘法设计习惯）。  
2. **勿同轴再乘**：例如亡灵层不要再叠「听亡增伤%」若池内已大量听亡/退场技能；护卫层勿再乘「挨打加攻%」与坚韧技能同轴叠爆。  
3. **军乐防白板墙**：四鼓无主技能，易凑军乐人数；军乐成形宜偏**节奏/状态**，且有技能的鼓手/号手应是核，白板鼓不应单独最优。  
4. **双计膨胀**：双标角色抬两表；Content 控制双标比例；团队层保持弱、门槛少档。  
5. **对外**：八主题名可以对玩家显示；内部「坚韧 / 冲锋」等流派称呼仍可不对外，避免两套名打架。

---

## 8. 玩家可读与验收（L0）

1. 文档与花名册能为每名可招友方读出主/辅主题。  
2. 规格写清：上场计数、双计、备战与随从不计。  
3. 成形后团队层须可通过统一效果管线描述（实现前可用占位效果验收管线，不以具体点数门禁）。  
4. **As-Is**：本版实现未接主题字段与发放前，地图/战斗不因本文自动出现羁绊 HUD。

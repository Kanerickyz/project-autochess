# 角色单位

> 功能规格 · 只谈规则与结构，不写具体数值 · 2026-10-12  
> 相关文档：[游戏愿景](../GAME_VISION.md) · [技能目录](../ABILITIES.md) · [商店](../SHOP_SYSTEM.md) · [增益](../BUFF_SYSTEM.md) · [角色一览](../UNITS_ROSTER.md)  
> **本版不写**：具体生命/攻击数字、暴击百分比、每回合走几格、伤害公式里的系数。这些交给数值策划和战斗规则去填。

## 1. 这是什么

**角色单位**规定：棋盘上所有能参与战斗的角色——友方角色、敌方角色、生成的代理角色——在「买卡构筑 → 摆位 → 开战看戏」里共用哪些身份、属性和技能约定。

| 阶段 | 角色单位在做什么 |
|------|------------------|
| 构筑 | 友方角色是商店里能买的卡；自带技能和流派标签决定你想怎么搭 |
| 布阵 | 生命、攻击、移动决定谁适合站前排、谁适合站后排 |
| 开战 | 普通攻击怎么打，和技能什么时候触发，是两套事；清光敌人算赢，己方全灭算输（见愿景） |

第一版的乐趣来自：角色自带技能的组合 + 站位 + 增益卡。**不做**「凑齐若干同族/同职业就触发团队加成」那种羁绊。

## 2. 写什么、不写什么

### 2.1 本文要说清的

- 单位有哪几种：友方角色、敌方角色、生成的代理角色
- 战斗相关属性怎么分：生命、攻击、移动
- 身份、技能槽、流派标签各自管什么
- 哪些是角色本身自带的，哪些是牌库里养成的，哪些只在本场战斗临时存在
- 生成代理角色时最少要约定什么
- 站位和空间上，角色之间怎么互相「用得上」
- 和商店、增益、战斗规则分别接到哪里

## 3. 单位种类

| 种类 | 是什么 | 怎么出现在棋盘上 |
|------|--------|------------------|
| **友方角色** | 玩家能在商店买到、放进自己阵容的角色 | 商店 → 牌库 → 准备阶段摆上棋盘 |
| **敌方角色** | 这一关/这一场对面的角色 | 按遭遇或波次配置刷出来 |
| **生成的代理角色** | 技能或效果在战斗里变出来的角色（替身、召唤物等） | 由技能或效果生成；默认不进商店，也不走牌库养成 |

三种都共用同一套「生命 / 攻击 / 移动」结构；差别见后文适用表和「生成的代理角色」一节。

---

## 4. 设计时先看哪些面

```text
说明身份的：种类 · 技能槽 · 流派标签
战斗用的：生命 · 攻击 · 移动
关系上的：由谁生成（主要针对代理角色）
和商店交接的：品阶、价格、击杀掉落金币等（本篇只说「有没有」，不定价）
```

| 面 | 为什么不算第四种「战斗属性」 |
|----|------------------------------|
| 种类与身份 | 决定能不能买、算哪一边、清场谁算赢，不直接算单次伤害 |
| 技能槽 | 管「什么时候额外发生什么」，和普通攻击怎么打是分开的 |
| 流派标签 | 方便策划和玩家认「这是什么打法」；**不是**凑数量触发的羁绊 |

## 5. 属性怎么设计

### 5.1 生命

| 属性 | 是什么意思 | 玩家什么时候在意 |
|------|------------|------------------|
| **生命上限** | 最多能挨多少伤害 | 摆前排、估能不能扛住 |
| **当前生命** | 这一场里还剩多少 | 开战过程中；上场时一般从「有效上限」开始 |

牌库养成和本场临时效果都能改生命相关数值（见第 6 节）。**具体数字本版不定。**

### 5.2 攻击

#### 攻击相关属性

| 属性 | 是什么意思 | 说明 |
|------|------------|------|
| **攻击力** | 算伤害时统一用的那个数 | 普通攻击的伤害由「基于攻击力的公式」算出来；具体公式和系数本版不定 |
| **攻击范围** | 普通攻击够得着多远 | 跟矩形棋盘上的战斗距离说法一致；具体几格本版不定 |
| **攻击暴击率** | 打出暴击的概率 | 具体百分比本版不定 |
| **攻击方式** | 普通攻击这一套循环怎么打 | 和技能是两套系统（见下） |

**已经拿掉**：单独的「攻击基础伤害」。不要再搞一套和攻击力并列的基础伤害字段。

#### 攻击方式 和 技能：两套系统（已定）

| 系统 | 管什么 | 不管什么 |
|------|--------|----------|
| **攻击方式** | 普通攻击：打不打、打多远、以什么形态出手 | 不负责整条「事件连锁」的技能逻辑 |
| **技能** | 角色自带的触发与效果（可以造成伤害、生成代理角色、加状态等） | 不重新定义「普通攻击怎么打」 |

技能造成的伤害可以**用到攻击力**（同一个数），但那仍是技能打出来的，不是攻击方式本身。

#### 攻击方式（先定大类）

| 方式 | 一句话 |
|------|--------|
| **标准普通攻击** | 按攻击范围，对目标打出基于攻击力的普通攻击 |
| **没有普通攻击** | 不走普通攻击循环；输出主要靠技能等 |
| **特殊攻击形态（以后再展开）** | 留给「改变命中形状或出手时机」的扩展；本版不写具体实现 |

**还没定**：「打得远」算单独一种攻击方式，还是「标准普通攻击 + 更大的攻击范围」（见开放问题）。  
特殊形态的细则本版不写（附录 B）。

### 5.3 移动

| 属性 | 是什么意思 |
|------|------------|
| **移动方式** | 怎么选格子、怎么挪过去 |
| **移动距离** | 一轮行动里，这种移动方式最多能动多少（具体数字本版不定） |
| **可不可以移动** | 这一场会不会走位（可以是角色自带，也可以被规则临时关掉） |

方式和距离分开看：方式回答「怎么走」，距离回答「能走多远」。

#### 移动方式——目前的设计提案（还没正式拍板）

下面 6 种是讨论里收束过的说法。你还没口头说「就用这套」；**如果后面没有异议，可以升成定稿。**

| 名称 | 一句话 |
|------|--------|
| **标准步进** | 一格一格靠近目标；一轮能走多远由移动距离限制 |
| **快速步进** | 和标准步进一样走法，但相对走得更远（只分类型，不定步数） |
| **滑移** | 沿一条直线一直滑，直到被挡住或到边 |
| **跳跃** | 中间格子不算阻挡，直接落到规则允许的远处格子 |
| **传送接近** | 不沿路径走，直接出现在靠近目标的合法空格 |
| **不可移动** | 这一场不走位 |

**还没定**：滑移要不要在本版再拆成「只能横竖 / 只能斜 / 都能滑」。

#### 和现在程序里的对照（只作参考，不是设计定稿）

程序里拆得更细（好几种步进、滑移、跳跃、传送等），也有「每回合移动量」一类字段。功能规格以上面的提案为准往回收；程序怎么映射，等定稿后再对齐。**不要把代码里的枚举名直接当成设计定稿。**

### 5.4 三种单位分别要填什么

| 项目 | 友方角色 | 敌方角色 | 生成的代理角色 |
|------|----------|----------|----------------|
| 单位种类 | 必填 | 必填 | 必填 |
| 能不能进商店 | 能 | 不能 | 不能 |
| 主技能 | **必须有** | 可以没有 | 可以没有 |
| 额外被动 | 可以有 | 可以有 | 可以有 |
| 流派标签 | 建议至少有一个 | 可以有 | 可以有 |
| 生命 / 攻击 / 移动 | 都要有 | 都要有 | 都要有（可以很简单） |
| 牌库里养成（星级、永久加成） | **会** | 不会 | **默认不会** |
| 由谁生成 | 一般不用 | 不用 | **建议写清楚** |
| 品阶 / 价格 | 要有（和商店交接） | 不用 | 不用 |
| 被击杀掉落金币 | 可以配 | 建议有 | 可以配 |

## 6. 自带的、牌库养成的、本场临时的

| 层 | 包括什么 | 活多久 |
|----|----------|--------|
| **角色自带** | 种类、挂上的技能、生命/攻击/移动的底板 | 跟着角色模板 |
| **牌库养成** | 星级、永久加攻加血等、部分规则标记 | 这一整局里、跟着牌库里那一张；**默认只有友方角色** |
| **本场临时** | 这一场战斗里对攻、血、范围、暴击等的临时改动 | 一场战斗；结束清掉 |
| **规则标记** | 例如不可移动 | 常由增益写到牌库条目上，开战时带到场上 |

```text
角色自带的底板
  → 牌库里的养成 / 增益 / 规则（友方角色）
    → 场上这一只（当前生命 + 本场临时改动）
```

星级怎么攒、升级加什么，写在商店文档里；本篇只钉死一点：**敌方角色和生成的代理角色，默认不走牌库养成。**

## 7. 技能槽约定

| 槽 | 约定 |
|----|------|
| **主技能** | 友方角色**必须**有；写给人看时，最好能读成「什么时候触发 + 对谁 + 发生什么」 |
| **被动** | 可以有，也可以没有 |
| **开战时** | 主技能和被动都会参与监听（增益若允许带进战斗，边界见增益文档） |
| **完整积木表** | 触发、目标、效果类型见 [技能目录](../ABILITIES.md)，这里不重复罗列 |

和前面一致：技能可以造成伤害，但不定义普通攻击怎么打。

---

## 8. 流派标签

| 约定 | 说明 |
|------|------|
| **干什么用** | 帮玩家和策划认出「这是什么打法」，方便做目录和教学 |
| **不是羁绊** | **禁止**「场上凑齐 N 个同标签就给全队加成」 |
| **和愿景里的说法** | 「坚韧」「冲锋」是体验上的别名，映射到标签；不再另开一套战斗属性 |
| **现状参考** | 角色一览里曾按触发类型（受伤、开战、召唤、死亡等）自动归类；那只是索引，不是资源里的定稿 |

**还没定**（见开放问题）：

- 一个角色只能有一个标签，还是可以有多个
- 标签清单定稿，以及要不要取消「其他」
- 「坚韧 / 冲锋」和标签怎么一一对应

---

## 9. 站位和空间（先说清楚的部分）

| 约定 | 含义 |
|------|------|
| **同一块矩形棋盘** | 友方、敌方、生成的代理角色占同一张格子；一格最多站一个 |
| **攻击范围** | 普通攻击够得着多远（和棋盘战斗距离说法一致） |
| **移动落点** | 受移动方式、移动距离、阻挡和占格限制 |
| **相对位置** | 技能里可以用「身后」「前排/后排」「周围格子」等；本篇承认这些是摆阵时用得上的空间说法，细则在技能文档 |

邻接和距离继续用现有矩形棋盘规则，不用六边形或其它体系替换。

---

## 10. 生成的代理角色

| 项目 | 约定 |
|------|------|
| **是什么** | 技能或效果在战斗里变出来的角色，默认是临时的 |
| **最少要有什么** | 生命、攻击、移动都要有；主技能可以没有；**建议写明是谁/什么效果生成的** |
| **养成** | 默认不进牌库星级，也不挂增益 |
| **生成时改数值** | 生成当下改生命等，算「生成效果」的约定，不必改代理角色模板本身 |
| **胜负和占格** | 算场上的实体；会影响清场和格子够不够用 |

## 11. 和商店、增益、战斗怎么交接

| 交接项 | 本篇怎么说 | 细节看哪 |
|--------|------------|----------|
| 品阶 / 价格 | 友方角色要有；和品阶怎么对齐见商店文档 | [商店](../SHOP_SYSTEM.md) |
| 买、卖、同名合并升级 | 改的是牌库里那一张；可能触发商店阶段的技能 | [商店](../SHOP_SYSTEM.md) |
| 击杀掉落金币 | 角色可以单独配；不配就走经济默认 | 经济 / 战斗 |
| 挂增益 | 只挂在牌库里的友方角色上；不改角色模板上的自带技能定义 | [增益](../BUFF_SYSTEM.md) |
| 清波胜负 | 敌方清空则胜，己方全灭则败 | [游戏愿景](../GAME_VISION.md) |
| 伤害怎么算 | 以攻击力为统一输入；具体公式另定 | 战斗规则 + 数值策划 |

# 战斗观战反馈

> 功能规格 · 开战观战时技能触发与结果如何让玩家看懂 · 2026-10-14  
> 相关文档：[战斗](./COMBAT.md) · [角色技能](./UNIT_ABILITIES.md) · [角色单位](./UNITS.md) · [增益](../BUFF_SYSTEM.md) · [游戏愿景](../GAME_VISION.md)  
> **本版不写**：完整战斗日志面板；普攻伤害飘字；流派/小队标签；音效具体资源表；精确像素与字号定死。  
> **【To-Be】** 实时战斗内：技能触发 → **时停播报队列**（含高频）+ 结果数字 / UI·动画；普攻只靠血条。开战锁阵（部署时 / 游戏开始）只播动画·UI，**不**走时停队列。**【As-Is】** 实时战场仅有溅射/死亡等几何 FX；旧格子环有飘字/callout/日志但未接主路径。

## 1. 这是什么

**战斗观战反馈**规定：玩家点开战之后、只能观战之时，如何从画面上读懂「构筑的联动有没有兑现」——尤其是角色技能触发后发生了什么。

它不管准备入座与胜负规则（见 [战斗](./COMBAT.md) / [玩家](./PLAYER.md)），也不管技能何时触发、强度如何评估（见 [角色技能](./UNIT_ABILITIES.md)）。本篇只定**表现层可读约定**：什么必须弹出、何时时停、队列怎么排、什么默认安静。

体验目标：纯观战仍能验证「事件 → 效果」因果，而不是只看见血条在动。

---

## 2. 写什么、不写什么

### 2.1 本文要写清的

- 主通道与非目标（本版不做战斗日志）  
- **技能时停播报队列**（实时战斗内）  
- 开战锁阵与实时战斗的反馈分工  
- 哪些结果必须飘字 / 短提示，哪些降噪或省略  
- 普攻与技能结果的分工  
- 友方优先、敌方下限  
- 加速与时停队列的关系  
- 玩家可观察验收口径  

### 2.2 和别处怎么分

| 本篇负责 | 别处负责 |
|----------|----------|
| 观战可读：时停队列、飘字类型、短提示、降噪 | **战斗**：三步流程、出兵时机、开战锁阵生成序、胜负 |
| — | **角色技能**：触发大类、频率分档、不露流派标签 |
| — | **角色单位**：血条、占位、移动攻击逻辑 |
| — | **技术美术 / UI**：具体皮肤、字号像素、色盲皮肤实现 |

### 2.3 一句边界

本版**不做**常驻战斗日志、普攻伤害飘字、全屏横幅、流派标签喊话、时停播报的跳过 / 清空队列。

## 3. 术语

| 术语 | 意思 |
|------|------|
| **结果数字** | 挂在单位旁的短弹出：技能造成的伤害/治疗、临时属性变化（如 `+攻`）等 |
| **短提示** | 技能显示名或极短人类说明（不露内部 id、不露流派/小队标签） |
| **交战层** | 普攻命中等基础交战；本版用血条变化表达，不强制飘字；**不**入时停队列 |
| **技能因果层** | 技能/战斗钩子增益结算后的可读反馈 |
| **时停** | 暂停固定步长模拟推进，专供当前技能播报可读 |
| **播报队列** | 待展示的技能因果条目按序排列；同时刻或多角色连锁触发时排队，不并行叠播 |
| **合并窗** | 短时间内同单位同类结果数字可合并展示，避免数字刷屏（**不**用来跳过时停入队） |

## 4. 主通道【设计定稿】

| 项 | 定稿 |
|----|------|
| 主通道（实时战斗） | **时停播报队列** + 战场结果数字 + 短提示 / 一次动画 |
| 单位常驻可读 | 剪影**下方左右**：攻击（深色色块）/ 生命（红色色块）；白描边 + 白字（参考小动物自走棋） |
| 战斗日志 | **本版不做**常驻可回看日志 |
| 普攻伤害飘字 | **默认不做**；普攻命中靠血条与下方生命数字更新（及已有受击闪白等） |
| 模拟关系（实时战斗） | 技能因果触发时**暂停**固定步长推进，按队列播报；队列清空后恢复推进。效果数值按规则先结算，时停不改已结算真值 |
| 开战锁阵 | 部署时 / 游戏开始：**不**走时停队列；只播动画 / UI 提示（见 §5） |

特效服务技能因果（愿景）：玩家应能指认「发生了技能效果」，而不是只看到结局胜负。

## 5. 两段反馈节奏【设计定稿】

### 5.1 开战锁阵（尚未进入实时战斗）

见 [战斗](./COMBAT.md) §6.5。此时战场时钟尚未进入自动战斗步进。

| 项 | 定稿 |
|----|------|
| 时停队列 | **不用** |
| 反馈 | 部署时 / 游戏开始若技能结算，播**动画或 UI 提示**（可含短提示 / 结果数字）即可 |
| 顺序 | 仍按锁阵生成与事件顺序结算；表现跟随该顺序，但不暂停「实时战斗时钟」（该时钟尚未启动） |

### 5.2 实时战斗内：时停播报队列

进入 §7 自动战斗之后适用。

| 项 | 定稿 |
|----|------|
| 入队范围 | **所有**技能因果层触发均入队，**含高频**（受伤时涨攻、出手小幅加成等） |
| 不入队 | 普攻交战层（血条 / 生命数字即可） |
| 单条内容 | **时停** + UI / 动画告知「谁、因何、发生了什么」+ 必要结果数字 / 短提示 |
| 初始时停时长 | **0.4s**（单条播报的时停起点；加速可缩短表现寿命，但不取消队列、不改为「不等播完就推进」） |
| 同刻 / 连锁 | 同一时间多个角色技能触发，或 A 的技能触发 B 的技能 → **全部排入同一队列**，FIFO：先触发先播；连锁产生的新条目排在当前条之后，不打断当前播报 |
| 跳过 | **本版不能跳过**当前条，也不能清空队列 |
| 队列空 | 恢复固定步长模拟推进 |

```text
技能因果触发（含高频）
  → 效果按规则结算
  → 入播报队列（FIFO；连锁追加到队尾）
  → 取出队首：时停（初始 0.4s）+ UI/动画/结果数字
  → 下一条…
  → 队列空 → 恢复实时推进
```

## 6. 何时必须反馈【设计定稿】

对齐 [角色技能](./UNIT_ABILITIES.md) 频率分档；**入队规则见 §5.2（高频也入队）**。

| 档位 / 结果形态 | 反馈 |
|-----------------|------|
| 一场一次、偶尔多次、条件稀有 | **入队时停**；结果数字或可见结果（生成/退场/换位）+ 短提示 |
| 高频（受伤时涨攻、出手小幅加成等） | **同样入队时停**；结果数字为主；短提示可从简，但不得因高频而跳过时停 / 不出队 |
| 普攻命中 | **交战层**：血条；不入队；不飘普攻伤害数字 |
| 生成代理、换位/击退、明显属性跳变 | **入队时停**；非数字可用短标/一次剪影特效 |
| 技能造成的伤害 / 治疗 | **结果数字**（仅技能管线结算才飘）并入该条播报 |
| 临时加攻等构筑兑现 | **结果数字**挂在**受益单位**上（如 `+攻`）并入该条播报 |

增益卡已在商店/卡面体现的持久属性，不在开战时重复刷屏；**战斗内临时跳变**才进战场弹出。

### 6.1 短提示何时出现

| 情况 | 短提示 |
|------|--------|
| 低频或条件稀有触发 | 带技能显示名（或等价短标） |
| 非数字效果（生成、换位等） | **建议**短名或图标二选一 |
| 高频 | 可从简；仍须有可辨认的 UI/动画或结果数字，并完成时停播报 |
| 文案 | 人类可读；**禁止**流派标签、「小队」标签、内部事件名 |

### 6.2 友方与敌方

| 侧 | 约定 |
|----|------|
| 友方 | **优先**满配可读（验证构筑） |
| 敌方 | 保威胁可读下限（尤其精英/Boss）；视觉预算可低于友方，但技能因果触发仍入队时停；敌方白板普攻只靠血条 |

## 7. 降噪与加速【设计定稿】

- 同单位、同结果类型、短合并窗内多次结果数字 → 可合并为一条展示（合计或带次数），但**合并后仍对应队列中的播报条**；不得用合并窗取消时停。  
- 同屏同单位同时可见弹出条数有上限；超出丢最旧或并入合并（不影响队列时停序）。  
- 加速观战：可缩短单条时停 / 动画寿命（不低于仍可扫读的下限），**必须按队列播完**再恢复推进；本版**无**跳过。  
- 形/字/动至少双通道（例如 `+攻` 字形 + 上浮）；伤/治/加攻不单靠红绿区分。

---

## 8. 玩家可观察操作与验收（L0）

1. 进入实时战斗后，友方技能触发时出现短暂时停，并有 UI/动画（及必要结果数字）能指认「技能效果发生了」。  
2. 高频技能触发同样入队时停，不会在无播报的情况下连续推进。  
3. 同刻多技能或连锁触发时，按队列逐条播报，不叠成无法分辨的一团。  
4. 普攻命中**不**出现普攻伤害飘字、**不**入时停队列；血条仍变化。  
5. 开战锁阵（部署时 / 游戏开始）有动画或 UI 提示，但**不**使用实时战斗的时停队列。  
6. 本版无常驻战斗日志；本版不能跳过时停播报。  
7. 加速可缩短单条时长，但不取消队列；胜负与已结算数值不因表现速度改变。  

**【As-Is】** 实时主路径尚未具备时停队列与上述飘字；验收待实现后启用。

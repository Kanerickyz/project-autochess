# 战斗观战反馈

> 功能规格 · 开战观战时如何让玩家看懂「谁在动、技能有没有兑现」 · 2026-10-15  
> 相关文档：[战斗](./COMBAT.md) · [角色技能](./UNIT_ABILITIES.md) · [角色单位](./UNITS.md) · [增益](../BUFF_SYSTEM.md) · [游戏愿景](../GAME_VISION.md)  
> **本版不写**：完整战斗日志面板；普攻伤害飘字；流派/小队标签；音效具体资源表；精确像素与字号定死；出手条 / 速度条 / CTB 仪表盘。  
> **【定稿】** 回合制依次行动：主通道 = **当前行动者高亮** + **一动一结算**；技能触发插入行动内播报（**先卡再执行**）。普攻只靠脚下生命标签。单动可压短，观战可加速。开战锁阵按生成序播动画·UI，不占用当前行动者通道。  
> **【As-Is】** 主路径已接行动队列与先卡再结算播报；旧格子环飘字/日志非主路径。

## 1. 这是什么

**战斗观战反馈**规定：玩家点开战之后、只能观战之时，如何从画面上读懂「现在轮到谁」以及「构筑的联动有没有兑现」。

它不管准备入座与胜负规则（见 [战斗](./COMBAT.md) / [玩家](./PLAYER.md)），也不管技能何时触发、强度如何评估（见 [角色技能](./UNIT_ABILITIES.md)）。本篇只定**表现层可读约定**。

体验目标：纯观战仍能验证「事件 → 效果」因果，而不是只看见生命数字在变；一次只强调一件正在发生的行动。

## 2. 写什么、不写什么

### 2.1 本文要写清的

- 主通道与非目标（本版不做战斗日志、不做出手条）  
- 开战锁阵与自动战斗的反馈分工  
- 一动内：走位 / 普攻 / 技能结果如何分工  
- 行动内技能连锁如何排队  
- 友方优先、敌方下限  
- 短演出与加速  
- 玩家可观察验收口径  

### 2.2 和别处怎么分

| 本篇负责 | 别处负责 |
|----------|----------|
| 观战可读：高亮、一动演出、飘字类型、短提示、降噪、加速 | **战斗**：三步流程、行动队列、一动语义、出兵时机、胜负 |
| — | **角色技能**：触发大类、频率分档、不露流派标签 |
| — | **角色单位**：脚下攻击 / 生命标签（不画头顶血条）、占位、移动攻击逻辑 |
| — | **技术美术 / UI**：具体皮肤、字号像素、色盲皮肤实现 |

### 2.3 一句边界

本版**不做**常驻战斗日志、普攻伤害飘字、全屏横幅、流派标签喊话、出手条/速度条、跳过当前这一动动画。

## 3. 术语

| 术语 | 意思 |
|------|------|
| **当前行动者** | 行动队列中正在执行一动的单位；须高亮，观战焦点落在它身上 |
| **结果数字** | 挂在单位旁的短弹出：技能造成的伤害/治疗、临时属性变化（如 `+攻`）等 |
| **短提示** | 技能显示名或极短人类说明（不露内部 id、不露流派/小队标签） |
| **交战层** | 普攻命中等基础交战；本版用生命标签数字变化表达，不强制飘字 |
| **技能因果层** | 技能/战斗钩子增益结算后的可读反馈 |
| **行动内播报** | 本动内触发的技能因果插入待执行队列的展示步骤；同动内连锁按 FIFO 播完再交下一动 |
| **技能展示步** | 单条播报的两拍：① 角色+技能介绍卡 → ② 执行/结算该技能并播结果数字/短提示 |
| **合并窗** | 短时间内同单位同类结果数字可合并展示，避免数字刷屏 |

## 4. 主通道【设计定稿】

| 项 | 定稿 |
|----|------|
| 主通道（自动战斗） | **当前行动者高亮** + **一动一结算** + 必要结果数字 / 短提示 / 一次动画 |
| 单位常驻可读 | 剪影**下方左右**：攻击（深色色块）/ 生命（红色色块）；白描边 + 白字（参考小动物自走棋） |
| 战斗日志 | **本版不做**常驻可回看日志 |
| 出手条 / 速度条 | **本版不做**主交付（串行感由行动队列与高亮承担） |
| 普攻伤害飘字 | **默认不做**；普攻命中靠脚下生命标签数字更新（及已有受击闪白等） |
| 与行动推进关系 | 同一时刻只推进**一个**当前行动者；其走位/出手/技能尾巴演完（或加速播完）后，才轮到队列下一名 |
| 开战锁阵 | 部署时 / 游戏开始：按生成与事件顺序播动画 / UI；**不**占用「当前行动者」高亮通道（见 §5） |

特效服务技能因果（愿景）：玩家应能指认「发生了技能效果」，而不是只看到结局胜负。

## 5. 两段反馈节奏【设计定稿】

### 5.1 开战锁阵（尚未进入行动队列）

见 [战斗](./COMBAT.md) §6.5。此时尚未从队首开始第 1 回合。

| 项 | 定稿 |
|----|------|
| 当前行动者高亮 | **不用**（锁阵不是行动队列上的一动） |
| 反馈 | 部署时 / 游戏开始若技能结算，播**动画或 UI 提示**（可含短提示 / 结果数字）即可 |
| 顺序 | 仍按锁阵生成与事件顺序结算；表现为第 0 段串行 |

### 5.2 自动战斗内：一动一结算（先卡再执行）

进入战斗篇 §7 之后适用。

| 项 | 定稿 |
|----|------|
| 焦点 | **高亮当前行动者**；其余单位不抢主镜头 |
| 一动内容 | 走位（落格顿步）→ 若出手则普攻交战层 → 该动内触发的技能按**行动内播报** FIFO 插入待执行队列并播完 |
| 普攻 | 交战层：生命标签数字即可；不飘普攻伤害数字 |
| 技能触发 | 触发当下**不立刻改数值**；把该技能的**技能展示步**插入当前待执行队列（可插在行动者一动尚未完成的后续步骤之前） |
| 技能展示步 | ① **先**显示触发者角色 + 技能介绍卡 → ② **再**执行/结算该技能 → 播结果数字/短提示 |
| 同动连锁 | A 行动中触发 B 的技能 → B 的展示步排在队尾；不打断当前正在播的那一条，也不提前开始下一名的一动 |
| 跳过 | **本版不能**跳过当前这一动或清空行动内播报 |
| 一动结束 | 行动内播报空且本动逻辑步做完 → 交队列下一名（或回合结束） |

```text
角色 A 行动
  → 高亮 A
  → A 靠近 / 出手（普攻靠生命标签）
  → B 的技能被触发 → 插入待执行队列：
       ① 显示 B + 技能介绍卡
       ② 执行技能（真值此时写入）+ 结果数字/短提示
  → 其他待处理行动 / 同动内后续展示步
  → 下一角色
```

## 6. 何时必须反馈【设计定稿】

对齐 [角色技能](./UNIT_ABILITIES.md) 频率分档；**入行动内播报规则见 §5.2（高频也入）**。

| 档位 / 结果形态 | 反馈 |
|-----------------|------|
| 一场一次、偶尔多次、条件稀有 | **行动内播报**；结果数字或可见结果（生成/退场/换位）+ 短提示 |
| 高频（受伤时涨攻、出手小幅加成等） | **同样入行动内播报**；结果数字为主；短提示可从简，但不得无表现地连跳 |
| 普攻命中 | **交战层**：生命标签数字；不飘普攻伤害数字 |
| 生成代理、换位/击退、明显属性跳变 | **行动内播报**；非数字可用短标/一次剪影特效 |
| 技能造成的伤害 / 治疗 | **结果数字**（仅技能管线结算才飘）并入该条播报 |
| 临时加攻等构筑兑现 | **结果数字**挂在**受益单位**上（如 `+攻`）并入该条播报 |
| 技能产金（`GRANT_GOLD`） | **结果数字** `+N金` + **金币纸片**（边长≈角色纸片 1/4；弹起再上浮淡出 Tween） |

增益卡已在商店/卡面体现的持久属性，不在开战时重复刷屏；**战斗内临时跳变**才进战场弹出。

### 6.1 短提示何时出现

| 情况 | 短提示 |
|------|--------|
| 低频或条件稀有触发 | 带技能显示名（或等价短标） |
| 非数字效果（生成、换位等） | **建议**短名或图标二选一 |
| 高频 | 可从简；仍须有可辨认的 UI/动画或结果数字 |
| 文案 | 人类可读；**禁止**流派标签、「小队」标签、内部事件名 |

### 6.2 友方与敌方

| 侧 | 约定 |
|----|------|
| 友方 | **优先**满配可读（验证构筑） |
| 敌方 | 保威胁可读下限（尤其精英/Boss）；视觉预算可低于友方，但技能因果仍进行动内播报；敌方白板普攻只靠生命标签 |

## 7. 降噪、短演出与加速【设计定稿】

- **短演出是规格一部分**：单动走位与出手、以及行动内播报单条，都以「能指认发生了什么」为下限，默认偏短。  
- 同单位、同结果类型、短合并窗内多次结果数字 → 可合并为一条展示；合并后仍对应行动内播报中的条目。  
- 同屏同单位同时可见弹出条数有上限；超出丢最旧或并入合并。  
- **加速观战**：可缩短单动移动/出手寿命与行动内播报条寿命（不低于仍可扫读的下限）；**必须按序播完**当前动再交下一动；本版**无**跳过。  
- 形/字/动至少双通道（例如 `+攻` 字形 + 上浮）；伤/治/加攻不单靠红绿区分。  
- 【建议】极简「第 N 回合」角标非必做（见战斗篇开放问题）。

### 7.1 单位程序动画（纯表现）

只改绘制偏移 / 旋转 / 缩放 / 闪白，不改结算与行动序；随观战倍速缩短。

| 时机 | 表现 |
|------|------|
| 走一格 | 以脚底为轴左右轻摆一次 + 小跳，与步进插值同步 |
| 出手前摇 | 攻击者后撤压扁蓄力；近战目标同步后撤迎击 |
| 近战出手 | 双方冲向对方对撞，撞上瞬间：受击者闪白 + 击退 + **震屏（幅度随实际扣血）**，随后弹回原位 |
| 远程出手 / 投射物命中 | 攻击者后坐；受击者闪白 + **震屏（幅度随实际扣血）** |
| 死亡 | 闪白后侧倒、缩小淡出；淡出结束即移除，不再绘制 |

### 7.2 长按查看单位

参考 SAP：在下列目标上按住约 0.4 秒弹出**同一张**信息卡：头像、名称、阵营 · 星级、攻血标、技能描述；松手收起。  
技能描述里的生命/攻击数值前使用与脚下标签相同的生命值/攻击力图标（如「恢复 [心]2」）。

| 覆盖 | 说明 |
|------|------|
| 准备座位、敌方预览、战斗中单位 | 已定 |
| 招募上区队伍 / 下区候选 | 已定 |
| **准备阶段卡面 / 未入座成员条**（As-Is 手牌卡面） | **To-Be**：与场上同一套长按手感与信息内容，便于布阵前读技能 |

按在单位 / 卡面上的点按动作推迟到松手，长按后不再触发（例如不会撤回已入座的角色、不会入座）；按下后移动超过约 10 px 不算长按。信息卡弹出期间松手只收卡。  
长按已弹出后，在单位间滑动切换介绍：卡面沿滑动方向倾斜抬起并弹性落位（小丑牌式跟手感）；手指停留时卡面轻跟微倾。  
同时**角色本体**抬起放大、沿滑动方向弹跳倾斜，非焦点单位略压暗缩小；焦点剪影置顶绘制。

## 8. 玩家可观察操作与验收（L0）

1. 进入自动战斗后，同一时刻能指认**当前行动者**（高亮或等价焦点）。  
2. 每一动演完（含该动技能尾巴）后，才轮到下一名；不会多人同时抢主镜头。  
3. 友方技能在对应行动内触发时，先看到角色+技能介绍卡，再看到效果结算（结果数字/可见变化）。  
4. 同动多技能或连锁时，按行动内播报逐条（先卡再执行）播出，不叠成无法分辨的一团。  
5. 普攻命中**不**出现普攻伤害飘字；生命标签数字仍变化。  
6. 开战锁阵（部署时 / 游戏开始）有动画或 UI 提示，且不与「当前行动者」通道混淆。  
7. 本版无常驻战斗日志、无出手条主交付；本版不能跳过单动动画。  
8. 加速可缩短演出，但不取消顺序；胜负与已结算数值不因表现速度改变。  

**【As-Is】** 主路径尚未具备当前行动者高亮与上述一动演出；验收待实现后启用。

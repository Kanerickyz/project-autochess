# 战斗观战反馈

> 功能规格 · 开战观战时技能触发与结果如何让玩家看懂 · 2026-10-14  
> 相关文档：[战斗](./COMBAT.md) · [角色技能](./UNIT_ABILITIES.md) · [角色单位](./UNITS.md) · [增益](../BUFF_SYSTEM.md) · [游戏愿景](../GAME_VISION.md)  
> **本版不写**：完整战斗日志面板；普攻伤害飘字；流派/小队标签；音效具体资源表；精确像素与字号定死。  
> **【To-Be】** 实时主路径：技能结果数字 + 稀有短提示；普攻只靠血条。**【As-Is】** 实时战场仅有溅射/死亡等几何 FX；旧格子环有飘字/callout/日志但未接主路径。

## 1. 这是什么

**战斗观战反馈**规定：玩家点开战之后、只能观战之时，如何从画面上读懂「构筑的联动有没有兑现」——尤其是角色技能触发后发生了什么。

它不管准备入座与胜负规则（见 [战斗](./COMBAT.md) / [玩家](./PLAYER.md)），也不管技能何时触发、强度如何评估（见 [角色技能](./UNIT_ABILITIES.md)）。本篇只定**表现层可读约定**：什么必须弹出、什么默认安静、信息落在哪。

体验目标：纯观战仍能验证「事件 → 效果」因果，而不是只看见血条在动。

---

## 2. 写什么、不写什么

### 2.1 本文要写清的

- 主通道与非目标（本版不做战斗日志）  
- 哪些结果必须飘字 / 短提示，哪些降噪或省略  
- 普攻与技能结果的分工  
- 友方优先、敌方下限  
- 加速观战与模拟分离  
- 玩家可观察验收口径  

### 2.2 和别处怎么分

| 本篇负责 | 别处负责 |
|----------|----------|
| 观战可读：飘字类型、短提示、降噪 | **战斗**：三步流程、出兵时机、胜负 |
| — | **角色技能**：触发大类、频率分档、不露流派标签 |
| — | **角色单位**：血条、占位、移动攻击逻辑 |
| — | **技术美术 / UI**：具体皮肤、字号像素、色盲皮肤实现 |

### 2.3 一句边界

本版**不做**常驻战斗日志、普攻伤害飘字、全屏横幅、流派标签喊话。

---

## 3. 术语

| 术语 | 意思 |
|------|------|
| **结果数字** | 挂在单位旁的短弹出：技能造成的伤害/治疗、临时属性变化（如 `+攻`）等 |
| **短提示** | 技能显示名或极短人类说明（不露内部 id、不露流派/小队标签） |
| **交战层** | 普攻命中等基础交战；本版用血条变化表达，不强制飘字 |
| **技能因果层** | 技能/战斗钩子增益结算后的可读反馈 |
| **合并窗** | 短时间内同单位同类结果合并为一条展示，避免刷屏 |

---

## 4. 主通道【设计定稿】

| 项 | 定稿 |
|----|------|
| 主通道 | **战场**上的结果数字 + **稀有**短提示 |
| 单位常驻可读 | 剪影**下方左右**：攻击（深色色块）/ 生命（红色色块）；白描边 + 白字（参考小动物自走棋） |
| 战斗日志 | **本版不做**常驻可回看日志 |
| 普攻伤害飘字 | **默认不做**；普攻命中靠血条与下方生命数字更新（及已有受击闪白等） |
| 模拟关系 | 表现订阅已结算结果；**永不**挡住固定步长模拟；加速可缩短表现寿命，不改判定 |

特效服务技能因果（愿景）：玩家应能指认「发生了技能效果」，而不是只看到结局胜负。

---

## 5. 何时必须反馈【设计定稿】

对齐 [角色技能](./UNIT_ABILITIES.md) 频率分档：

| 档位 / 结果形态 | 反馈 |
|-----------------|------|
| 一场一次、偶尔多次、条件稀有 | **必须可读**：结果数字或可见结果（生成/退场/换位）+ 需要时短提示 |
| 高频（受伤时涨攻、出手小幅加成等） | **结果数字为主**；默认**不**每次技能短提示；短窗可合并 |
| 普攻命中 | **交战层**：血条；本版不飘普攻伤害数字 |
| 生成代理、换位/击退、明显属性跳变 | **必须反馈**（非数字可用短标/一次剪影特效） |
| 技能造成的伤害 / 治疗 | **结果数字**（与普攻区分：仅技能管线结算才飘） |
| 临时加攻等构筑兑现 | **结果数字**挂在**受益单位**上（如 `+攻`） |

增益卡已在商店/卡面体现的持久属性，不在开战时重复刷屏；**战斗内临时跳变**才进战场弹出。

### 5.1 短提示何时出现

| 情况 | 短提示 |
|------|--------|
| 低频或条件稀有触发 | 可带技能显示名（或等价短标） |
| 非数字效果（生成、换位等） | **建议**短名或图标二选一 |
| 高频且已有结果数字 | **默认不带**短提示 |
| 文案 | 人类可读；**禁止**流派标签、「小队」标签、内部事件名 |

### 5.2 友方与敌方

| 侧 | 约定 |
|----|------|
| 友方 | **优先**满配可读（验证构筑） |
| 敌方 | 保威胁可读下限（尤其精英/Boss 的醒目技能结果）；视觉预算低于友方；敌方白板普攻只靠血条 |

---

## 6. 降噪与加速【设计定稿】

- 同单位、同结果类型、短合并窗内多次 → **合并**为一条（合计或带次数，实现任选一种并保持一致）。  
- 同屏同单位同时可见弹出条数有上限；超出丢最旧或并入合并。  
- 加速观战：可缩短停留，但不短于仍可扫读的下限；**不**采用「播完提示才推进战斗」的门闩。  
- 形/字/动至少双通道（例如 `+攻` 字形 + 上浮）；伤/治/加攻不单靠红绿区分。

---

## 7. 玩家可观察操作与验收（L0）

1. 开战观战中，友方技能导致的治疗、技能伤害、临时加攻等，在**受益或受害单位旁**出现结果数字（或约定短标）。  
2. 普攻命中**不**出现普攻伤害飘字；血条仍变化。  
3. 低频/非数字技能（如生成代理）有短提示或等价一次可见特效，能指认「技能效果发生了」。  
4. 高频叠层类不以每次全名喊话刷屏；短窗内可合并。  
5. 本版无常驻战斗日志面板。  
6. 加速后反馈可变快，战斗胜负与数值结果不因表现速度改变。  

**【As-Is】** 实时主路径尚未具备上述飘字；验收待实现后启用。

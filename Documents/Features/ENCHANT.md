# 附魔（神龛）

> 功能规格 · 地图 **附魔节点**：为一名队员授予 **Run 持久战斗词条** · 2026-11-16  
> 相关：[地图与节点](./MAP.md) · [战斗状态](./COMBAT_STATUS.md) · [玩家](./PLAYER.md) · [游戏愿景](../GAME_VISION.md) · [游戏循环](./GAME_LOOP.md)

## 1. 这是什么

**附魔**是地图上的非战斗节点：玩家在「**上：词条神龛 / 下：当前队伍**」里 **点选 1 名队员**，从本节点给出的 **战斗词条** 中 **择一确认**（或 **跳过**）。确认后，该队员获得 **整局 Run 持久** 的附魔；此后 **每场战斗开战** 时，自动按规则写入对应 **战斗状态**（见 [战斗状态](./COMBAT_STATUS.md)）。

体验骨架：路线兑一次 **单人特质** → 不改主技能、不献祭队友 → 与 **招募**（加人）、**地图商店**（装备/纹章）、**事件**（徽章等）分工不同；附魔是 **异常/特质向的队伍定制**。

**废止（不再做主路径）**：时机格 A / 效果格 B、80% 熔合检定、**熔印者**、`fused_enchant` 身份、runtime 技能缝合。

## 2. 写什么、不写什么

### 2.1 本文要写清的

- 何时进入 / 离开  
- 表现布局（上下半场、选人、词条候选）  
- 词条池、持久语义、与开战状态的衔接  
- 与装备、徽章、天生被动（如易燃易爆体质）的边界  
- 验收口径  

### 2.2 和别处怎么分

| 本篇负责 | 别的文档负责 |
|----------|----------------|
| 附魔节点内流程 | **地图**：节点种类、? 解析、完成回地图 |
| Run 持久「附魔词条」挂在 `DeckEntry` | **玩家**：队伍、席位、三合一 |
| 开战时写入 `CombatStatusStack` | **战斗状态**：各 id 结算规则 |
| — | **招募 / 商店**：不加词条货架 |
| — | **徽章**：挂玩家整局，非单人词条 |

### 2.3 一句边界

**做**：每节点 **至多兑现 1 次** 附魔（选人+确认词条）；跳过回地图；词条 **Run 持久**；开战施加状态。  
**不做**：献祭队员、熔印者、runtime 缝技能、花金随机抬成功率、改攻血/主技能、跨 Run 存档（另案）。

## 3. 术语

| 术语 | 意思 |
|------|------|
| **附魔节点** | 地图 `ENCHANT`；进房走本篇 |
| **战斗词条** | `CombatStatusStack` 中已定义的 **状态 id**（如 `volatile`、`berserk`）；附魔授予的是 **开战层数/规则**，不是新 Bus |
| **附魔授予** | 写在队伍条目上的 Run 字段；**仅 1 个 id**（新确认 **覆盖** 旧附魔） |
| **天生特质** | 单位 `UnitData` / 被动在 **OnCombatStart** 自带的状态（如爆爆 **易燃易爆**）；与附魔 **同 id 不叠层**（仍受状态上限约束） |

## 5. 表现与布局

### 5.1 镜头

与 [招募](./RECRUIT.md) / [地图商店](./MAP_SHOP.md) 同类：**半场滑入**；结束滑出回地图。

### 5.2 分区

| 区域 | 内容 |
|------|------|
| **上区** | 词条展示：**3 个候选**（或配置槽位数）；显示名 + 规则摘要（对齐战斗状态附属文案） |
| **下区** | 当前 **已入座队伍**（建议 **不含仅备战**，与商店拖装备一致） |
| **交互** | 点选队员 → 点选词条 → **确认**；未选人时确认不可用 |

竖屏：**上神龛下队伍**（与招募「上队下候选」可同向或镜像，实现与商店统一即可）。

### 5.3 底栏

| 按钮 | 作用 |
|------|------|
| **确认** | 写入附魔（见 §6）；本节点结束 |
| **跳过** | 队伍不变；回地图 |

本版 **不做**：重置炉位、融合掷骰、投币。

## 6. 规则

### 6.1 对象与次数

| 规则 | 说明 |
|------|------|
| **每次节点** | **至多 1 次** 成功附魔（确认后不可在同一节点再选） |
| **对象** | **恰好 1 名** 已入座队员 |
| **每人** | **至多 1 个** 附魔词条；新附魔 **覆盖** 旧 id 与层数配置 |
| **跳过** | 不消耗、不写附魔 |

### 6.2 词条池【建议 · 首版草案】

从 [战斗状态](./COMBAT_STATUS.md) 已实装 id 中抽 **小池**（数值写入配置 `.tres`，本文不定具体权重）：

| 类别 | 示例 id | 开战施加（草案） |
|------|---------|------------------|
| 特质 | `volatile` | 1 层（易燃易爆） |
| 进攻 | `berserk` | 1 层 |
| 异常 | `burn` / `poison` | **不开战叠层**；【建议】首版词条池 **不含** 纯 DOT 叠层，仅特质/狂暴类，避免与火焰刀/技能重复 |

每节点从池中 **独立随机 3 个** 展示（可重复款需数值约束）；**不含** 未在 `CombatStatusStack.is_valid_id` 登记的 id。

### 6.3 持久与开战

1. 确认时：在目标 `DeckEntry` 写入 **附魔 id + 开战层数**（层数由词条配置决定，特质类多为 1）。  
2. **每场战斗** `OnCombatStart`（或等同开战钩子）：对该实例 `APPLY_COMBAT_STATUS`，**仅 SELF**；与单位天生 `OnCombatStart` 被动 **顺序**：先天生、再附魔，或合并为「同 id 取 max(层数,1) 且不超过上限」。  
3. **遭遇结束**：战斗状态清空；**附魔字段保留** 在队伍条目，下一场再施加。  
4. **整局 Run 结束**（败 / Boss 通）：附魔字段随条目清空。

### 6.4 与相邻冲突

| 情况 | 规则 |
|------|------|
| 天生 `volatile` + 附魔 `volatile` | **仍为 1 层** volatile |
| 附魔不是装备/徽章 | **不占** 主装备槽、不进徽章栏 |
| 三合一 | 产物 **继承** 三源中 **随机一条** 的附魔（与装备合并规则同档简化）；无附魔则空 |

## 7. 数据契约（规格）

实现须满足：

1. `DeckEntry` 可存 **可选** `enchant_combat_status_id` + `enchant_stacks`（或等价 Resource）。  
2. `UnitInstance.sync_from_deck_entry` / 开战广播时施加附魔状态。  
3. 信息卡 **准备/战斗/招募** 可读附魔摘要（玩家词条，非遭遇内叠层预览）。  
4. **不** 再生成 `fused_enchant` 条目入主路径。

---

## 8. 与相邻系统

| 系统 | 关系 |
|------|------|
| **战斗状态** | 附魔只 **引用** 已有 id；新 id 须先改战斗状态篇 |
| **装备 / 武器** | 独立；可同一人又有毒刀又有附魔狂暴 |
| **徽章** | 团队规则；附魔单人 |
| **事件 / 商店** | 不卖附魔词条 |

## 9. 验收（To-Be）

1. 进附魔：上词条下队伍；可跳过回地图。  
2. 选人 + 确认后，该队员 **下一场及之后每场** 开战带约定状态（可长按验证）。  
3. 同节点不可二次确认；跳过队伍不变。  
4. 覆盖：同队员再获附魔时旧词条被替换。  
5. 无双献祭、无熔印者、无 80% 检定 UI。
